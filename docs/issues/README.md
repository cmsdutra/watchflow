# Issues

Itens de trabalho identificados mas não implementados, versionados junto do
código em vez de num rastreador externo — assim a análise chega no clone, e a
decisão fica lado a lado com o que ela decide.

Cada issue registra o que foi **medido**, e não o que se supõe. Quando um plano
depende de um comportamento da plataforma, esse comportamento é verificado na
máquina antes de virar linha do plano.

| # | Título | Prioridade | Estado |
|---|---|---|---|
| [001](001-notificador-desktop-windows.md) | Notificador desktop para Windows | alta | aberta |

Ao fechar uma issue: mude o **Estado** no cabeçalho do arquivo e nesta tabela,
e registre no commit o que ficou diferente do plano. Um plano que acertou tudo
é raro o bastante para merecer desconfiança.
